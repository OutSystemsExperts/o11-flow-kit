# Read-only model analysis (indexes, aggregates, SQL usage)

Verified 2026-10-22 on two O11 Reactive applications, each with a UI module and its Core Services module.

- `getDataModel` does NOT emit entity indexes. Its output is also too large for context (90-390 KB)
  and FK `DataType` lines come after all entities (forward refs), so line-by-line parsing mixes attributes.
- `runQuery` with `Entities { Indexes { ... } }` fails: "Schema is not configured correctly to fetch field
  'Indexes' from type 'StaticEntity'" and `IsUnique` does not exist on `EntityIndex`. Don't retry variants.
- `getSerializedObjectByNameAndType` (IServerEntity) does list indexes but omits `Unique` when false and is per entity.
- What works: one throw-probe per module (`startOmlEditSession` -> `applyModelApiCode` ending in
  `throw new Exception("PROBE:" + ...)` -> `endOmlEditSession`, nothing saved, `discardedChanges:false`). Emit one
  pipe-separated line per element:
  - entities: `eSpace.Entities.OfType<OutSystems.Model.Data.IServerEntity>()` (also yields static entities;
    use `en.EntityKind` = `Server`/`Static`), `a.DataType.DisplayName` ("X Identifier" = FK), `a.DeleteRule`,
    `en.Indexes` -> `ix.Unique`, `ix.AutoGenerated`, `ix.IndexAttributes.Select(x => x.Attribute.Name)`.
  - usage: `eSpace.GetAllDescendantsOfType<OutSystems.Model.Logic.Aggregates.IAggregate>()` ->
    `g.AsDatabaseAggregate` -> `Sources`, `Joins`, `Filters`, `Sorts` (`IsDynamic`), `GroupByAttributes`,
    `AggregatedAttributes`; `ISQLNode.Statement`; `IExecuteServerActionNode.Action.DisplayName` for the call graph.
  - owner path: walk `IModelObject.Parent` up to the `IESpace`, `GetType().Name + ":" + DisplayName`.
  - expression text: `expr.ToString()` cut at the first `" ["`.
- Output of a 60-entity Core module was ~70 KB: the harness saves it to a file; parse it with a script.
- FKs with Delete Rule `Ignore` get no `AutoIndex_*`; check them when a filter uses them.
